# Session Manager v1 API

This is a private RomM-to-Session-Manager contract. It is not a browser API.

All `/v1` routes require a high-entropy bearer service credential. Actor-scoped
mutations additionally require the stable authenticated user ID and display name in
the headers documented in `docs/milestone-7-session-manager.md`.

Create accepts only:

```json
{
  "display_name": "Saturday Night NES",
  "romm_rom_id": 42,
  "max_players": 2
}
```

Unknown fields are rejected. The trusted `RomMProvider` and `CoreRegistry`, not the
request, supply the platform, ROM hash, and core profile. Session and participant UUIDs
are generated by the service.

Expected responses are `201` for create, `200` for reads/join/leave, and `204` for
close. Domain failures use `403` for non-owner close, `404` for missing objects, and
`409` for capacity or state conflicts. Missing or invalid service authentication uses
`401`; malformed models and missing actor assertions use `422`.

Responses contain domain/lobby data only. They never contain ROM paths, core paths,
container identifiers, private IP addresses, Netplay ports, TURN credentials, or
Selkies master tokens.

An active participant requests browser launch material with:

```text
POST /v1/sessions/{session_id}/launch
```

The stable asserted actor must match an `ACTIVE` participant. The response contains
only that participant's public stream path, scoped controller token, and session lease
expiry:

```json
{
  "stream_path": "/stream/0123456789abcdef0123456789abcdef/",
  "access_token": "opaque-participant-token",
  "expires_at": "2026-09-02T16:00:00Z"
}
```

The caller appends the percent-encoded token as the Selkies bootstrap `token` query
parameter. Callers must not log the response or resulting URL. The token is distinct
from the server-only Selkies master token, is scoped to one runtime as controller of
its local gamepad slot 1, and is valid no later than the session lease expiry.


Active participants renew their heartbeat and the bounded lobby lease with:

    POST /v1/sessions/{session_id}/heartbeat

The stable asserted actor must match an active participant. The response is the
updated session. Renewal cannot extend beyond the server-configured maximum session
lifetime. Missing heartbeats retire an idle guest; an idle or absent owner closes the
whole lobby. Runtime health failures follow the same host-versus-guest policy. See
[Milestone 10 lifecycle](../milestone-10-session-lifecycle.md) for timings and restart
behavior.
The owner can retire a non-owner participant with:

```text
POST /v1/sessions/{session_id}/participants/{participant_id}/kick
```

Leave, kick, close, and session expiry replace the runtime's Selkies token table with
an empty object before removing the runtime. Kicking the owner is rejected; close the
session instead.

Milestone 18 adds authenticated operator-safe reads:

```text
GET /v1/operations/capacity
GET /v1/sessions/{session_id}/diagnostics
```

Capacity reports the configured maximum and current/available managed-runtime slots.
Session diagnostics correlate session/participant lifecycle state with runtime state and
health. They intentionally omit user IDs, display names, ROM hashes and paths, container
identifiers, private addresses, tokens, and credentials. `/metrics` is a separate private
Prometheus scrape endpoint and is not routed through the public edge.
